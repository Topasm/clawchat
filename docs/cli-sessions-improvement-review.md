# CLI 세션 관리 개선 검토

검토일: 2026-09-25

참고 대상은 우선 OpenAI의 공개 Codex와 공식 App Server 문서로 해석했다.
별도 프로젝트를 뜻하는 경우 해당 저장소와의 비교는 추가로 필요하다.
현재 ClawChat 서버·웹·Android 구현을 읽고 개선 후보를 정리한 문서이며,
아래 항목의 구현 완료를 의미하지 않는다.

## 우선순위

| 순서 | 개선 | 현재 확인한 문제 | 완료 조건 |
| --- | --- | --- | --- |
| 1 | JSON-RPC 메시지 분류 수정 | `CodexConnection.call()`이 ID만 비교한다. 같은 ID의 서버 요청을 성공 응답으로 오인할 수 있다. | 요청·알림·응답을 먼저 구분하고, 요청별 응답을 정확히 전달한다. ID 충돌과 이벤트 교차 수신 테스트를 통과한다. |
| 2 | 연결 진단과 복구 안내 | 소켓 연결 예외가 사라지고 일반적인 연결 실패 안내만 남는다. 현재 PC의 실시간 연결 실패 원인을 화면에서 확인할 수 없다. | CLI 탐지, 소켓 접속, 초기화, API 호출 실패를 구분한다. 마지막 성공 시각과 연결 대상을 표시하고 재연결할 수 있다. |
| 3 | 지속 연결과 공유 조회 | API 요청마다 연결을 열고 닫는다. 기록 조회로 대체될 때는 조회마다 별도 프로세스를 실행한다. | 호스트 연결을 공유하고 중복 조회를 합친다. 재연결 간격을 늘리며 재시도하고, 기록은 짧게 캐시한다. 클라이언트 수만큼 CLI 실행이 늘지 않는다. |
| 4 | 승인·질문 모아 보기 | Codex의 승인 대기와 질문 대기가 같은 상태로 합쳐진다. 구체적인 요청 내용과 응답 기능이 없다. | 지원되는 연결에서 요청별 내용·대상 세션·유효 상태를 보존하고 모바일에서 답한다. 다른 클라이언트가 처리한 요청은 제거한다. |
| 5 | 실행 과정과 변경 파일 표시 | Codex 상세는 사용자·에이전트 메시지만 읽는다. 명령 실행, 종료 코드, 변경 파일, 계획을 표시하지 않는다. | 대화·실행 로그·변경 파일을 구분하고 각 작업의 진행 및 실패 이유를 볼 수 있다. |
| 6 | 프로젝트별 관리와 긴 기록 탐색 | 목록은 최근 기록 100개, 상세는 전체 이력을 받아 마지막 10턴만 표시한다. 웹은 상태 미확인을 저장 세션으로 표시한다. | 폴더별 묶음, 대기 항목 우선 표시, 기록 페이지 탐색, 상태 미확인/저장 기록 구분을 제공한다. |

## 재현된 통신 결함

대상: `server/execution/cli_sessions.py`, `CodexConnection.call()`.

모의 수신 순서:

1. 클라이언트가 ID `1`로 요청한다.
2. 서버가 ID `1`, method `item/commandExecution/requestApproval`인 요청을 보낸다.
3. 서버가 ID `1`, result `{"marker":"actual-response"}`인 응답을 보낸다.

현재 결과는 `{}`이며 첫 프레임만 소비한다. 실제 응답까지 읽지 않는다.
통신 상대가 양방향으로 요청할 수 있으므로 `method`가 있는 메시지는 응답과
구분해야 한다. 이 재현은 메모리 안의 모의 수신 함수로 실행했으며 실제
Codex·Claude 세션에 명령을 보내지 않았다.

후속 모델 업데이트 작업에서 응답 대기 중 서버 요청·알림을 응답으로
오인하지 않도록 수정하고 회귀 테스트를 추가했다. 승인 요청을 사용자에게
전달하고 응답하는 지속 연결 기능은 여전히 후속 과제다.

## 구현 근거

- `server/execution/cli_sessions.py`: 응답 분류, 연결 수명, 예외 처리,
  전체 기록 조회 및 메시지 종류 필터링.
- `server/routers/cli_session.py`: 요청마다 생성되는 기본 서비스.
- `src/app/hooks/queries/useCliSessionQueries.ts`: 5초 주기 조회.
- `src/app/components/runs/CliSessionsPanel.tsx`: 상태 미확인 표시,
  폴더·제목 문자열 검색, 평문 상세 출력.
- `android/feature/runs/src/main/java/com/clawchat/android/feature/runs/CliSessionsViewModel.kt`:
  목록·상세 재조회와 워크스페이스 변경 시 취소 처리.

## 적용 순서와 검증

먼저 메시지 분류와 연결 진단을 수정한다. 현재 실시간 연결 실패의 원인을
해결한 뒤 지속 연결과 이벤트 전달을 붙이고, 승인·질문 및 실행 내역을 확장한다.
연결 유지 자체만으로 기존 외부 세션의 이벤트 수신이 보장되지는 않으므로
설치된 버전의 구독 방식과 승인 요청 전달 대상을 검증해야 한다.

Codex·Claude의 실제 지원 기능은 각각 확인해 제공한다. Claude의 기존
포그라운드 세션을 앱에서 제어하는 기능은 이번 조사에서 새로 검증하지 않았다.
완료·승인 요청 알림은 이벤트 전달이 갖춰진 뒤 추가할 수 있다.

검증에는 실제 사용자 세션 대신 격리한 세션을 사용한다. 재연결 시 중복
명령이 발생하지 않는지, 두 화면에서 같은 승인 요청을 처리할 때 일관적인지,
워크스페이스가 바뀌면 이전 이벤트가 표시되지 않는지를 확인한다.
