# ClawChat v1.4.25

## macOS release signing safeguards

- Normal releases now require a complete Apple Developer ID signing and notarization configuration. Missing credentials no longer silently produce an ad-hoc signed macOS release.
- Temporary ad-hoc signing requires explicit workflow opt-in and warns that Keychain approval can recur after every update. Partial Apple credentials are rejected even with this opt-in.
- Added signing setup and two-release Keychain approval verification instructions, plus regression tests for signing configuration validation.

## Update notes

- This change hardens the release process; it does not bypass macOS permissions or change credential storage. Login data remains in the OS credential vault.
- Ad-hoc builds do not fix repeated Keychain prompts. Stable Developer ID signing must be configured before this behavior can be verified across updates. Switching from an ad-hoc build may require another approval.
- No application workflow or database migration changes are included. Real macOS Keychain approval persistence still requires testing with consecutive signed releases.
